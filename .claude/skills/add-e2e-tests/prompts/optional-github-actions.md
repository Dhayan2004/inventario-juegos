# optional-github-actions — workflow setup (solo modo full)

> Prompt operativo. Invocado por add-e2e-tests Fase 5 SOLO en modo `full`.
> **Cita:** `[memory:decisions#D-026]` (Mode B = full implica GitHub Actions),
> `[memory:CONSTRAINTS.md#R13]` (find-docs antes de generar actions YAML),
> `[docs:playwright]`, `[docs:github-actions]`.

---

## Precondiciones

- Mode = `full`.
- `.github/workflows/` writable.
- Si `.github/workflows/e2e.yml` YA existe → halt + diff con el template propuesto + esperar confirmación humana antes de modificar.

---

## Protocolo

### Paso 1 — find-docs (R13)

```
resolve-library-id("github-actions") + query-docs("setup-node cache npm matrix playwright")
resolve-library-id("playwright") + query-docs("playwright install --with-deps CI matrix")
```

Verificar:
- `actions/setup-node@v4` sigue siendo current (vs v3 deprecated).
- `actions/cache@v4` API estable.
- `actions/upload-artifact@v4` (no v3 — deprecated).
- `npx playwright install --with-deps` syntax actual.

### Paso 2 — Read template

```
Read .claude/skills/add-e2e-tests/templates/github-workflow.yml.template
```

### Paso 3 — Write `.github/workflows/e2e.yml`

- Header del archivo cita:
  ```yaml
  # Generated by add-e2e-tests Mode FULL.
  # [memory:decisions#D-026] · [docs:playwright] · [docs:github-actions]
  ```

- Matrix por browser:
  ```yaml
  strategy:
    fail-fast: false
    matrix:
      browser: [chromium, firefox, webkit]
  ```

- Cache strategy:
  - `actions/setup-node@v4` con `cache: 'npm'` (built-in npm cache).
  - Browser cache separado: `actions/cache@v4` keyed por `playwright-${{ runner.os }}-${{ hashFiles('**/package-lock.json') }}`.

- Steps canónicos:
  1. `actions/checkout@v4`
  2. `actions/setup-node@v4` (node-version: '20', cache: 'npm')
  3. `npm ci`
  4. Cache de browsers (~/.cache/ms-playwright)
  5. `npx playwright install --with-deps ${{ matrix.browser }}`
  6. `npm run test:e2e -- --project=${{ matrix.browser }}`
  7. `actions/upload-artifact@v4` con `playwright-report/` (only if failure())

### Paso 4 — Validación post-write

```bash
# YAML syntax check (sin acción ejecutiva)
python3 -c "import yaml; yaml.safe_load(open('.github/workflows/e2e.yml'))" 2>&1 \
  || node -e "require('js-yaml')" 2>&1  # fallback si python3 no está
```

- Exit 0 esperado en alguno de los dos.
- Si ambos fallan (ningún parser disponible) → skip validation con warning al usuario.

### Paso 5 — Triggers del workflow

Por default:
```yaml
on:
  push:
    branches: [main]
  pull_request:
    branches: [main]
```

Permitir override via discovery suave:
- Si el usuario pidió "solo en PRs" → quitar el push block.
- Si el usuario pidió "en todas las branches" → cambiar `branches: [main]` a `branches: ['**']`.

Default conservador (push a main + PRs a main) si no hay señal.

---

## Refusals

- ❌ Sobrescribir `.github/workflows/e2e.yml` existente sin confirmación humana.
- ❌ Generar workflow sin find-docs (actions versions pueden estar deprecated).
- ❌ Subir credenciales reales al workflow. `TEST_USER_EMAIL` + `TEST_USER_PASSWORD` deben venir de GitHub Secrets, NO hardcoded.
- ❌ Setear `fail-fast: true` en matrix — queremos saber qué browser falló, no abortar al primer fail.
- ❌ Saltar `--with-deps` en `playwright install` en CI (deps de webkit/firefox son críticas en Ubuntu runners).
