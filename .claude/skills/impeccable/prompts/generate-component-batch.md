# generate-component-batch — init core component set

> Operational prompt para Mode C. Toma `brand.json` y produce el set completo de componentes declarados en `component_rules` × sus variants.
>
> **Source schema:** [memory:references#R-005].
> **Trigger típico:** init de proyecto fresh tras cierre de `add-ui-kit`.

---

## Input esperado

```yaml
brand_json: brand/brand.json (asumido válido)
target_dir: src/shared/components/ui  # default
extras:
  scope?: "all" | "core" | "minimal"
    # all      = todos los component_rules × todas las variants
    # core     = button + card + form (input/textarea/select) + modal.confirm
    # minimal  = solo button + form.input
  with_barrel?: boolean   # default true (genera index.ts re-export)
  with_types?: boolean    # default true (genera types.ts compartido)
```

## Procedimiento (6 pasos)

### Paso 1 — Read brand.json + plan

```python
brand = read_json("brand/brand.json")

components = []
for name, rules in brand["component_rules"].items():
    for variant in rules["variants"]:
        components.append((name, variant))

# Para TECH UTILITY example:
# components = [
#   ("button", "primary"), ("button", "secondary"), ("button", "ghost"), ("button", "danger"),
#   ("card", "default"), ("card", "interactive"), ("card", "metric"), ("card", "empty"),
#   ("form", "text"), ("form", "search"), ("form", "textarea"), ("form", "select"),
#   ("modal", "confirm"), ("modal", "form"), ("modal", "detail"),
#   ("navigation", "sidebar"), ("navigation", "topbar"), ("navigation", "tabs"), ("navigation", "breadcrumb")
# ]
# Total: 19 component-variant pairs
```

Filtrar por `scope`:
- `all` → 19 pairs (TECH UTILITY)
- `core` → 13 pairs (button × 4, card × 4, form × 4, modal.confirm)
- `minimal` → 2 pairs (button.primary, form.text)

### Paso 2 — find-docs (R13) — UNA VEZ por sesión

Pre-loop, no per-component. Citar las 3 invocaciones en el header de cada TSX.

### Paso 3 — Generate por componente (loop)

Por cada componente único (no per variant — multiple variants viven en un mismo TSX):

```
a. Read templates/<Component>.tsx
b. Compose all variants para ese component en un solo cva()
c. Apply Mode A pipeline (skip find-docs, ya cached)
d. Generate TSX → src/shared/components/ui/<Component>/<Component>.tsx
e. Validate-anti-slop (per-file)
f. Compute brand-score (per-file)
g. Si score < 75 → regenerate (max 3 retries por componente)
```

Notas especiales:
- `Form` es un caso de fragmentación: NO un solo `Form.tsx` con cva masivo. En vez, **un archivo por primitive**: `Input.tsx`, `Textarea.tsx`, `Select.tsx`. Razón: cada uno tiene su shape de props distinto (input value=string vs select onChange=event con label).
- `Navigation` similar: cada variant es estructuralmente distinta. Sidebar tiene aside semantics, Topbar es header, Tabs es role="tablist", Breadcrumb es nav con ol/li. Cada uno su propio TSX.

## Casos edge

### Variant exótica fuera del set canónico (ej: button.marketing)

Si `brand.json.component_rules.button.variants` declara una variant que el template no cubre:
- Generar la variant aplicando el lookup más cercano del set canónico (ver `prompts/generate-component-known.md` paso 4 lookup table)
- Registrar warning en el report del batch
- el-evaluador puede promover a errors.md (E-NNN) si la variant es recurrente cross-project

### shadcn-ui detectado en target

Si `package.json` o `components.json` indica shadcn-ui instalado:
- Mode C delega la base a shadcn (button, card, input shadcn primitives) y SOLO sobreescribe la cva con tokens de brand.json
- Reduce duplicación con shadcn upstream
- Documentar en commit message + en `references/shadcn-mapping.md`

Sin shadcn detectado:
- Mode C genera primitives Tailwind from-scratch (lo descrito en este prompt)

### Re-batch (re-generar tras editar brand.json)

Si los componentes ya existen y `brand.json` cambió:
1. Detectar cambio: comparar el hash del brand.json embedded en cada componente vs el actual
2. Re-generar SOLO los componentes que tocan tokens cambiados
3. Preservar customizaciones manuales del usuario en archivos separados (ej: `Button.custom.tsx`) — NO sobreescribir
4. Reportar el delta

---

## Refusals

- ❌ Generar el set completo si brand.json no pasa PREFLIGHT.
- ❌ Saltar paso 6 (final gate sobre todo el set).
- ❌ Sobrescribir customizaciones manuales del usuario.
- ❌ Mergear si AVG Brand Score < 75.
