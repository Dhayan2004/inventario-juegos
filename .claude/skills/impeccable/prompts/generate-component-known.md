# generate-component-known — variant declarado en component_rules → component code

> Operational prompt para Mode A. Toma un input `<component>.<variant>` que **YA EXISTE** en `brand.json.component_rules` y produce el archivo TSX correspondiente.
>
> **Source schema:** [memory:references#R-005] (component_rules en sección 9.1).
> **Templates:** `templates/<Component>.tsx` con placeholders.
> **Reference outputs:** `references/examples-tech-utility.md`.

---

## Input esperado

```yaml
component: "button" | "card" | "form" | "modal" | "navigation"
variant:   <string>  # debe estar en brand.json.component_rules.<component>.variants
target_path: src/shared/components/ui/<Component>/<Component>.tsx  # default
extras:
  use_client?: boolean    # default false (Server Component)
  with_states?: boolean   # default true
```

## Output esperado

`src/shared/components/ui/<Component>/<Component>.tsx` + (si new) `index.ts` barrel.

## Procedimiento (7 pasos)

### Paso 1 — PREFLIGHT verificada por SKILL.md

Asume que SKILL.md ya validó:
- brand.json + voice.json + brand.css existen
- brand.json cumple R-005

Si dudás → re-validar antes de seguir.

### Paso 2 — Validate input vs component_rules

```python
component_rules = brand_json["component_rules"]

    halt(f"{component} no está en component_rules. ¿Es Mode B (UNKNOWN)?")

variants = component_rules[component]["variants"]

    halt(f"variant '{variant}' no declarada para {component}. Disponibles: {variants}. ¿Querés Mode B (UNKNOWN)?")

```

### Paso 4 — Resolve variant-specific tokens

| Component | Variant | Default token map (TECH UTILITY example) |
|-----------|---------|-------------------------------------------|
| button | primary | bg=primary, text=white, hover-opacity-90, focus-ring=primary |
| button | secondary | bg=surface, text=text, border=border, hover bg=surface-elevated |
| button | ghost | bg=transparent, text=text-muted, hover text=text |
| button | danger | bg=danger, text=white, hover-opacity-90 |
| card | default | bg=surface-elevated, border=border, rounded=radius-md |
| card | interactive | + hover bg-surface-higher + cursor-pointer + transition |
| card | metric | + display font on number + mono on label |
| card | empty | + text-muted body + center alignment |
| form.input | text | bg=surface, border=border, focus-ring=primary, rounded=radius-md |
| form.input | search | + magnifier icon left + debounced onChange |
| modal | confirm | overlay=surface/80 + dialog=surface-elevated + cancel/confirm row |
| navigation | tabs | flex row + active state via primary border-bottom |

Si la variant no está en la tabla, derivar consultando `references/examples-tech-utility.md` que tiene 6 implementaciones canónicas.

### Paso 5 — Render template + apply rules

Cargar `templates/<Component>.tsx` y substituir:

| Placeholder | Source |
|-------------|--------|
| `{{ COMPONENT_NAME }}` | PascalCase del component (Button, Card, ...) |
| `{{ VARIANTS }}` | Array TS de variants declaradas |
| `{{ DEFAULT_VARIANT }}` | typically 'default' o 'primary' |
| `{{ ALLOWED_BEHAVIORS }}` | brand.json.archetype.allowed_behaviors |
| `{{ MOTION_FAST }}` | `var(--motion-duration-fast)` |
| `{{ MOTION_BASE }}` | `var(--motion-duration-base)` |
| `{{ TOKEN_USAGE_MAP }}` | mapping computed en paso 4 |

Aplicar las **rules** (R-005 sección 3.1) como assertions runtime + JSDoc:

Para `button`:
- "Only one primary action per view section" → JSDoc del Button.tsx
- "No diagonal gradients" → assertion en cva variant primary: NO `bg-gradient-*-to-*`
- "Focus, hover, active, disabled and loading states required" → todas las variants implementan los 5
- "Icon must clarify the action" → `iconLeft?` + `iconRight?` props con docstring

### Paso 6 — Generate TSX con cva pattern

Estructura canónica:

```typescript
'use client'  // SOLO si necesita state/effects

/**
 * <Component> · variants: <list>
 *
 * Generated by impeccable from brand/brand.json (component_rules.<component>).
 * Variants declared in component_rules.<component>.variants.
 *
 * Citations:
 *   [memory:references#R-005] schema (component_rules sec 3 + 9.1)
 *   [memory:CONSTRAINTS.md#R10] Brand DNA contract gate
 *   [docs:tailwindcss] arbitrary value var() syntax
 *   [docs:shadcn-ui] cva pattern + ComponentProps<>
 *   [docs:react] Next.js App Router server/client component policy
 *
 * Rules enforced (from brand.json.component_rules.<component>.rules):
 *   <list each rule as JSDoc bullet>
 */

import { cva, type VariantProps } from 'class-variance-authority'
import { cn } from '@/lib/cn'  // standard helper, asumido o creado por add-ui-kit
import { forwardRef, type ComponentPropsWithoutRef } from 'react'

const <component>Variants = cva(
  // base classes — siempre presentes
  'inline-flex items-center justify-center font-medium transition-colors disabled:opacity-50 disabled:pointer-events-none focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-[var(--color-primary)] focus-visible:ring-offset-2 focus-visible:ring-offset-[var(--color-surface)]',
  {
    variants: {
      variant: {
        primary: 'bg-[var(--color-primary)] text-white hover:opacity-90 active:opacity-80',
        secondary: '...',
        ghost: '...',
        danger: 'bg-[var(--color-danger)] text-white hover:opacity-90',
      },
      size: {
        sm: 'h-8 px-3 text-sm rounded-[var(--radius-sm)]',
        md: 'h-10 px-4 text-sm rounded-[var(--radius-md)]',
        lg: 'h-12 px-6 text-base rounded-[var(--radius-md)]',
      },
    },
    defaultVariants: { variant: 'primary', size: 'md' },
  }
)

type <Component>Props = ComponentPropsWithoutRef<'button'> &
  VariantProps<typeof <component>Variants> & {
    iconLeft?: React.ReactNode
    iconRight?: React.ReactNode
    isLoading?: boolean
  }

export const <Component> = forwardRef<HTMLButtonElement, <Component>Props>(
  function <Component>({ className, variant, size, iconLeft, iconRight, isLoading, children, ...props }, ref) {
    return (
      <button
        ref={ref}
        className={cn(<component>Variants({ variant, size }), className)}
        aria-busy={isLoading}
        disabled={isLoading || props.disabled}
        {...props}
      >
        {isLoading ? <Spinner /> : iconLeft}
        {children}
        {iconRight}
      </button>
    )
  }
)
```

## Casos edge

### Variant existe en component_rules pero el template no la cubre

Si `brand.json.component_rules.button.variants` incluye una variant exótica (ej: `"marketing"`) que el template canónico no tiene:
- Ofrecer al usuario: ¿agregar al template (commit feat(impeccable))? ¿usar Mode B (UNKNOWN derivation)?
- Sin respuesta → default Mode B sobre la base de la variant más cercana.

### Component mismatch (request "drawer" pero brand.json no declara drawer)

Halt + redirect a Mode B (UNKNOWN). Sugerir lookup en `references/derivation-rules.md`.

### use_client necesario pero no declarado en input

Detectar:
- Si el componente tiene `useState`/`useEffect` → necesita `'use client'`
- Si solo recibe props y renderiza → Server Component
- Si event handlers (onClick, onChange) y NO ssr-only → `'use client'`

Aplicar automáticamente + documentar en commit.

---

## Refusals

- ❌ Generar variant que NO está en `component_rules.<component>.variants`.
- ❌ Hardcodear hex/font/spacing — siempre via `var(--*)` tokens.
- ❌ Saltar validate-anti-slop o compute-brand-score.
- ❌ Mergear con Brand Score < 75.
- ❌ Sobrescribir un componente existente sin que el orchestrator confirme.
